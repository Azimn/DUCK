# DUCK Documentation Authority

This file defines which documents govern the current repository.

## Current life-simulation candidate

`ARCHITECTURE_v0.7.md` is the binding architecture for the thirty-day life-simulation candidate.

`MILESTONE_0_7.md` is the executable simulation and acceptance contract for that candidate.

`STATUS.md` records what is actually implemented and what CI has verified.

`DONOR_AUDIT_v0.1.md` is nonbinding research context. Donor mechanisms do not become DUCK requirements merely because they appear in that document.

## Historical architecture

`ARCHITECTURE_v0.6.md` and `MILESTONE_0_6.md` remain preserved as the first longitudinally regulated whole-organism baseline. They are historical snapshots of the candidate promoted to `main` before the v0.7 life-simulation refinements.

`ARCHITECTURE_v0.5.md` and `MILESTONE_0_5.md` remain preserved as the first whole-organism FrankenDUCK integration. They are historical snapshots of the pre-regulation implementation.

`ARCHITECTURE_v0.1.md` and `MILESTONE_0_1.md` remain preserved as the original Subjective Moment milestone. They are historical snapshots and should not be silently edited to describe later architecture.

The older `DUCK_Unified_Subject_Architecture_Design_Spec_v0.3` from `Azimn/persona_engine_PYTHONX` is not the current architecture of this repository. Other Wayfarer, Ensemble, subjective-access, portability, sensor, or embodiment documents in older repositories remain donor/history material unless explicitly reintroduced here.

## Development doctrine

The v0.5 integration sprint deliberately assembled mechanisms broadly. Version 0.6 shifted emphasis to longitudinal regulation. Version 0.7 extends that doctrine to simulated life: run the same persistent individual through recurring relationships, misinformation, commitments, repair, learning, quiet time, and restart boundaries, then treat implausible long-horizon composition as an architecture defect rather than hiding it behind fluent language.

That simulation-led development does not relax the first-person access firewall or subject-authority rules.

## Future modalities

Vision, audio, touch, proprioception, interoception, avatars, robotics, XR, and richer embodiment remain future surfaces. The architecture-level rule is already fixed: machine representations must cross the same subject-access boundary before they become available to the simulated subject.
